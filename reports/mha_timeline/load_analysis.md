# 完整 block 分布分析与下一步

证据：ff0cc25:error.txt，是对 2026-10-29 同一次采集目录的离线导出，
不是新一轮性能测量。两侧各 32 个 block 标签，每个含 cube0/vector0/vector1，合计 96 行。
block_id 不能直接等同物理核编号，也不能用 32 个标签推翻设备查询得到的 28 AIC。

## 实测分布

时间单位 us，表内是跨 block 的 min / median / max。

| 指标 | KV2 | S2 |
|---|---|---|
| AIC 时间 | 24.658 / 26.482 / 26.848 | 24.682 / 26.147 / 27.074 |
| AIV vector0 时间 | 24.990 / 26.840 / 27.216 | 25.022 / 26.507 / 27.439 |
| Cube 计算时间 | 19.859 / 19.859 / 19.859 | 19.859 / 19.859 / 19.859 |
| AIC MTE2 时间 | 18.865 / 24.737 / 25.058 | 18.101 / 24.128 / 24.465 |
| AIC Fixpipe 时间 | 16.265 / 16.636 / 17.749 | 17.170 / 17.807 / 18.504 |
| AIV vector0 计算时间 | 21.019 / 21.445 / 21.646 | 21.054 / 21.376 / 21.553 |
| AIC 标量时间 | 2.361 / 3.091 / 3.723 | 1.794 / 2.391 / 3.119 |

两侧标签 14、15、30、31 的 AIC MTE2 时间都明显较短，约 18–19 us，
多数其他标签约 24–25 us；这四个标签的 block 执行时间也较短。
可以作为调度/缓存差异的线索，但没有启动时间和物理核映射，不能定性为第二波任务。

S2 的 block 时间中位数略小，最大值反而略大；不可只看单个统计值断言全面改善。
两侧 Cube 计算时间相同，vector 计算时间接近。值得继续查的是流水线重叠、
数据搬运及同步依赖，而不是据此认定计算指令数量减少。
这些管线并行工作，跨 block 的中位数还可能来自不同 block，不能相加后从总时间中相减。

## 不能从当前数据得出的结论

- block 本身没有两倍慢的离群值，但缺少起止时间，不能排除分批调度。
  单 block 约 26 us 与全任务约 54 us 的比例只是线索，不能直接量化调度尾部占比。
- AIC 读缓存命中率中位数约 96.19%（S2）和 96.75%（KV2），仍不能单独排除
  数据搬运瓶颈；命中率没有给出关键路径、事务数及带宽饱和情况。
- S2 的 aiv_vec_wait_ratio 最大值 1.030915，aiv_mte3_wait_ratio 最大值也超过 1。
  在当前工具/芯片指标定义尚未核实前，保留原始数值，不能解释为等待时间占比，
  更不能据此宣称 99% 时间空闲或有对应加速空间。
- 本次没有 AscendC 采集数据，不更新双方加速比。
